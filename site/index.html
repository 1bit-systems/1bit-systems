1bit Coding Agent

A full pi.dev-compatible coding agent harness. 7 commands, NPU-native inference, extensions, skills, themes, and package management — all local, no cloud.

$ 1bit
  Usage: 1bit <command> [options]

  Agent commands:
    chat              Start interactive agent session (default)
    install <pkg>     Install a package (npm:, git:, or path)
    remove <pkg>      Remove an installed package
    list              List installed packages
    update [pkg]      Update 1bit and packages
    config [key=val]  View or set configuration

  NPU stack commands:
    up        Start NPU stack (lemond + API bridge)
    down      Stop NPU stack
    status    Show NPU stack health
    build     Build NPU engine from source
Chat

Interactive readline session with slash commands (/help, /status, /clear, /exit, /model). Direct NPU API queries via SSE streaming. Branded 1bit banner.

Packages

install|remove|list|update — npm:/git: specs. Delegates to pi's package manager. Persists in ~/.1bit/agent/settings.json.

Config

Theme, default provider, model, thinking level, NPU endpoint. All persist across sessions.

Extensions

pi-compatible extension API. Ships 1bit-npu extension with 4 tools: npu_status, npu_up, npu_down, npu_query.

Skills

SKILL.md system for instructing the model. Ships NPU management and agent architecture skills.

Systemd

User-level service auto-starts the agent on boot. install-service.sh for install/uninstall/status.

Install

Builds the ROCm ternary engine, Rust HTTP server, and all tools. Requires Strix Halo (gfx1151) with ROCm 7.2+.

git clone https://github.com/bong-water-water-bong/1bit
cd 1bit
cmake -B build -G Ninja -DCMAKE_HIP_ARCHITECTURES=gfx1151
ninja -C build rocm_cpp bitnet_decode bench_prefill_variants
cd rust && cargo build --release

Then run inference:

export HSA_OVERRIDE_GFX_VERSION=11.5.1
export HSA_ENABLE_SDMA=0
export LD_LIBRARY_PATH=build:$LD_LIBRARY_PATH
./build/bitnet_decode model.h1b --text "Hello Bonsai!" 128

1bit monorepo

Five engines

Hand-written, dependency-free, benchmarked on the metal.

ROCm ternary (RDNA 3.5)

Custom HIP C++ kernels. Bonsai-1.7B TQ2 at 113 tok/s. 28.4 TFlops prefill. 48.5 GB/s GEMV BW. Zero Python.

ZINC (multi-backend)

Zig GLSL compute → SPIR-V. Qwen3.5-9B Q4_K. GGUF native. 27 µs decode. 7.8× rocBLAS.

MLX (Apple + XDNA 2)

Apple MLX fork with IRON XDNA 2 backend. Same framework runs on M1–M5 AND your NPU.

Sherry 3:4 sparse

N:M sparse ternary GEMV — 19.3 GB/s, ~2,588 tok/s. Experimental PolyForm-NC licensed.

The five rules

These rules describe the product boundary.

Rule A

Core serving stays Python-free. Training, notebooks, build-time conversion, and caller-side tools are allowed.

Rule B

C++20/23 for kernels. HIP code in rocm-cpp/; Rust and TypeScript above the kernel boundary.

Rule C

hipBLAS banned in the runtime path. Port kernels to rocm-cpp/.

Rule D

Rust 1.88+, edition 2024. Bumps require a reason.

Rule E

FastFlowLM is the XDNA serving lane. Custom NPU kernels use IRON → MLIR-AIE → Peano → xclbin.

Carve-out

Open WebUI is a secondary compatibility UI. It does not become the engine.

Architecture

1bit monorepo
├── rust/          axum HTTP server → spawns bitnet_decode
├── src/           HIP C++ kernels → ternary GEMV/GEMM
├── kernels/       HIP implementations → phase5, sherry, kv-cache
├── include/       C API headers → prefill_tuner.h, ck_gemm.h
├── tools/         Benchmarks, sweeps, model exporter
└── site/          1bit.systems website

bitnet_decode (CLI)
  → librocm_cpp.so (shared library, RDNA 3.5 WMMA)
  → Bonsai-1.7B TQ2 · .h1b + sidecar .gguf

onebit (Rust HTTP server)
  → spawns bitnet_decode --server
  → OpenAI-compatible /v1/* API on :13305
