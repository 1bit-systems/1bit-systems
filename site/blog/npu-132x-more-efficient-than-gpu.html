Why the NPU is 132× more efficient than the GPU for LLMs

tl;dr: The XDNA 2 NPU delivers 145 tok/s/W vs the GPU's 1.1 tok/s/W — a 132× efficiency advantage. The NPU is not "a weaker GPU." It's a fundamentally different architecture.

The headline numbers

MetricNPU (~2W)GPU (~20W)Ratio
LLM throughput291 tok/s22 tok/s13×
tok/s per watt1451.1132×
TFLOPS55.7~124.6×
TFLOPS per watt27.80.646×

Measured on a Ryzen AI Max+ 395 — NPU vs Radeon 8060S GPU, same die, same memory, same model.

Why the NPU wins

1. Spatial dataflow, not SIMD

A GPU spends significant power on instruction fetch/decode, warp scheduling, and register file access. The XDNA 2 NPU is a spatial dataflow architecture — compute tiles are configured with a fixed dataflow graph at load time. Data streams through 32 AIE tiles directly. Zero instruction overhead during compute.

2. SRAM locality

Each AIE tile has 64KB local SRAM. The Chess compiler maps operations so intermediate results stay local — no trips to system memory. A GPU's "local" memory is shared L1/L2 cache with hundreds of threads competing. For a transformer layer, the NPU keeps the entire activation vector (6KB at INT8) in local tile memory through the entire pipeline.

3. No kernel launch overhead

GPU inference requires a kernel launch for every operation. The NPU fused layer does all operations in one xclbin call. No driver round-trips between operations.

The power breakdown

GPU ~20W: Memory controller ~4W, shader array ~10W, cache hierarchy ~4W, driver overhead ~2W, actual compute ~2W. ~85% on infrastructure.

NPU ~2W: Compute tiles ~1.2W, SRAM access ~0.5W, interface ~0.3W. ~60% on actual compute.

What this means

Running NPU inference at 291 tok/s: ~0.6W additional draw, no fan noise, runs 24/7 on battery.

Running GPU inference: ~18W, fan spins up, 2-3h battery vs 20+ hours.

132× more tok/s per watt. The NPU isn't competing with the GPU. It's making the GPU irrelevant for local LLM inference.
