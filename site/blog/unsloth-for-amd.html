Unsloth for AMD — Train & Fine-Tune LLMs on Radeon, Instinct & Ryzen AI

tl;dr: Unsloth released native AMD GPU support for LLM training, fine-tuning, reinforcement learning, and inference. Up to 2x faster with 70% less VRAM. Runs on as little as 3GB VRAM (Qwen3.5, Gemma 4). Covers Radeon, Instinct, Ryzen AI (including Strix Halo's Radeon 8060S), and data-center GPUs — across Windows, WSL, and Linux.

Why this matters for Strix Halo owners: Unsloth lets you train on the same AMD hardware where 1bit.systems handles inference. Complementary stack: train with Unsloth on the GPU, deploy with 1bit on the NPU+GPU.

Benchmarks (MI300X)

Unsloth published LLM fine-tuning benchmarks on an AMD MI300X (192GB HBM):

Llama-3.1-8B LoRA SFT — training speed 1.39x faster (2.07 vs 2.87 s/step)
Llama-3.1-8B LoRA SFT — VRAM 1.33x less (18.3 vs 24.3 GB)
VRAM reduction vs. TRL + FA2 70% less
GRPO RL VRAM reduction 80% less
Total training time (25 steps) 56s vs 75s (1.34x)
Key insight: The VRAM savings hold for the entire run, not just peak. Unsloth stays flat at ~18.3 GB while TRL+FA2 spikes to 22.8 GB on nearly every step.

How AMD Support Was Built

Unsloth ported their custom kernels to AMD in collaboration with AMD's engineering team. Key PRs:

  • #2520 — ROCm kernels: HIP/Triton ports tuned for RDNA and CDNA, with architecture-specific precision, performance, and stability fixes
  • #3748 — 4-bit training: bitsandbytes-based QLoRA support for Radeon and CDNA GPUs
  • #4770 — Automatic setup: robust AMD GPU detection and correct ROCm PyTorch wheel installation, including repair and platform safeguards
  • #5301, #6227 — Windows and Strix Halo: native Windows ROCm installation, runtime compatibility patches, unified-memory reporting, and WSL support
  • #5172 — ROCm inference: architecture-specific llama.cpp prebuilts, source-build fallback, AMD VRAM detection, and monitoring

Key Features Available on AMD

  • LoRA / QLoRA fine-tuning (4-bit bitsandbytes for Radeon + CDNA)
  • GRPO (Reinforcement Learning) — 80% less VRAM than alternatives, with weight sharing via vLLM to halve memory
  • No LoRA merging drift — Unsloth uses vLLM's LoRA path directly, avoiding IEEE rounding errors from merge/unmerge cycles in BF16
  • Full fine-tuning and pretraining
  • 4-bit, 16-bit, and FP8 quantization
  • Long-context training — 500K+ context, 3x faster packing
  • Multi-GPU training (Linux only via RCCL; Windows lacks GPU-collective backend)
  • GGUF inference with hardware controls (GPU layer placement, MoE expert offloading) via daily ROCm llama.cpp prebuilts
  • Tool call healing — 50% accuracy increase on function-calling
  • Unlimited free web search, HTML canvases, code execution
  • Vision / multimodal models
  • Embedding and TTS fine-tuning
  • Secure HTTPS deployment via Cloudflare tunnels
  • Phone access — train and chat from your phone via Cloudflare link

Unsloth Dynamic (UD) GGUFs — What You're Actually Downloading

When you see a model like unsloth/gemma-4-E2B-it-GGUF:UD-Q4_K_XL, the UD- prefix means it's an Unsloth Dynamic quant — a selective-layer quantization method that upcasts important layers to 8/16-bit while aggressively quantizing less critical layers. This lets massive models like DeepSeek-V3.1 (671B) fit in ~192 GB at 1-bit or ~229 GB at 2-bit.

Available UD Variants

VariantBit-widthDescriptionUse Case
UD-TQ1_0~1-bitDynamic 1-bit, extreme compressionMinimal RAM — 192 GB for 671B models

UD-Q2_K_XL~2.7-bitRecommended — best size/accuracy balance, faster conversion than IQ2_MGeneral purpose — 220 GB for GLM-5.1

Downloading UD Models

hf download unsloth/GLM-5.1-GGUF \
    --local-dir unsloth/GLM-5.1-GGUF \
    --include "*UD-Q2_K_XL*"

# Dynamic 1-bit
hf download unsloth/GLM-5.1-GGUF \
    --local-dir unsloth/GLM-5.1-GGUF \
    --include "*UD-TQ1_0*"

Or with Python:

from huggingface_hub import snapshot_download
snapshot_download(
    repo_id="unsloth/GLM-4.7-GGUF",
    local_dir="unsloth/GLM-4.7-GGUF",
    allow_patterns=["*UD-Q2_K_XL*"],
)
1bit.systems compat: These are standard GGUF files under the hood — the engine's GGUF loader auto-detects architecture from metadata, same as any other GGUF. No special handling needed.

Installing Unsloth on AMD

Quick install (Linux / WSL):

curl -fsSL https://unsloth.ai/install.sh | sh

Windows (PowerShell):

irm https://unsloth.ai/install.ps1 | iex

pip install (for notebooks / code):

uv pip install unsloth[amd]

Launch Unsloth Studio:

unsloth studio -p 8888

# For remote / phone access via HTTPS:
unsloth studio --secure

Detailed guide:

https://unsloth.ai/docs/basics/amd

Connecting to Agent Frameworks

Unsloth's unsloth start command connects locally trained/fine-tuned models to agents:

unsloth start claude    # Claude Code
unsloth start codex    # OpenAI Codex
unsloth start hermes   # Hermes Agent
unsloth start pi       # Pi Coding Agent
unsloth start openclaw
unsloth start opencode

You can also serve as a subagent with a specific model:

unsloth start claude --as-subagent --model unsloth/gemma-4-E2B-it-GGUF:UD-Q4_K_XL

Community Reception & Known Issues

The announcement was well received — 65+ upvotes, broadly positive. Key highlights from the Reddit thread:

Hardware people are running

  • Dual RX 7900 XTX
  • RX 6900, RX 9060 XT
  • Ryzen AI MAX+ 395 (Strix Halo) — significant interest from the community around unified memory training
  • MI300X (192GB) via AMD Developer Cloud

Early bugs

  • ROCm version fallback — ROCm 7.14 detected but falls back to 7.2 on Strix Halo. Unsloth team acknowledged and investigating.
  • Strix Halo Windows VRAM — Unsloth doesn't recognize dedicated VRAM on Windows with unified memory APUs.
  • Vision projector / llama.cpp — Compatibility issue with certain GGUF builds.
  • GPU detection — Installer sometimes reports "CPU-only" on Strix Halo before the ROCm torch backend is selected.

Future work

  • Expanded CI/CD using AMD Strix Halo and Radeon Lab hardware
  • Support for new AMD GPU architectures as they launch
  • Clearer multi-GPU guidance (Windows currently limited)
  • Further speed optimizations for the ROCm stack
