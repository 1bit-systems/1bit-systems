NPU Architecture Multi-Platform

One binary to rule them all — 5 model families, auto-detect

tl;dr: A single 38KB binary reads the Q4NX header of any supported model, auto-detects architecture dimensions, and dispatches to the right backend. Zero config files.

The model explosion problem

73+ models across 6 backends. The naive approach: 73 config files. One per model. Each a maintenance nightmare.

Better approach: read the model's own header.

The Q4NX header

AMD's Q4NX format packs everything needed to reconstruct the model: num_layers, hidden_size, num_heads, num_kv_heads, head_dim, intermediate_size, vocab_size, rope_theta, norm_eps, and data_offsets for every weight tensor.

The engine parses these at startup, allocates the right buffers, and dispatches to the correct GEMM kernels. The same binary that runs Qwen3-0.6B (1,536 hidden, 12 layers) also runs Llama-3.1-8B (4,096 hidden, 32 layers).

The one-line fix that unlocked 5 models

dequant_i8_to_float_ex had in_features hardcoded to 1024 — only Qwen3-0.6B worked. Fixing it to read H, NH×HD, and IM per-projection from the header: one line. Five new models.

73+ models. 6 backends. One 38KB binary. The header knows what it is. The binary figures out the rest.
